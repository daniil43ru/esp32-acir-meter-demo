The problem with the usual DIY approach

Most hobby IR meters use a load pulse: push a current step into the cell, watch the voltage sag, divide. The trouble is that the sag also includes the contact resistance of your spring holders — 5–20 mΩ on an 18650, which is the same order as the quantity being measured. A 50% error is typical and it looks like perfectly good data.

This project measures with a Kelvin connection: current flows through one pair of leads, voltage is sensed across a second pair that carries no current. Lead and contact resistance drops out physically rather than by calibration.

Signal chain

// excitation path (current)
GPIO25 ── 1 kHz square ── Cdc 10µF ── Rforce ── Rshunt ──┬── cell +
                                                              │
                                                            [ Ri ]
                                                              │
                                                       cell − ── GND

// sense path (no current, so no lead-resistance error)
cell + ── Cin 1µF ── LM358 IN+ ── ×48 ── GPIO35 ── lock-in I/Q

What the firmware actually does

  • Lock-in detection over 2000 samples — the naive min/max envelope overestimates by up to +95% at 5 mV of noise.
  • I/Q offset removal — a vector subtraction, not a scalar one.
  • Median of 5 readings to kill impulsive interference.
  • Conversion against a reference resistor (K_CAL) to absorb part tolerances.
  • Diagnostics screen: phase, signal level, ADC saturation flag.
  • OLED UI: main / voltmeter / diagnostics / calibrate.

Verify it without a soldering iron

The signal math is checked by four Python tools that run on any laptop:

python tools/model_check.py    # signal chain, resolution, calibration effect
python tools/test_lockin.py    # asserts on the detector — exits 1 on failure
python tools/test_settling.py  # op-amp settling vs measurement window
python tools/test_timing.py    # what happens when the loop overruns

Honest about what is not done

This has never been assembled on a breadboard. The circuit is a best-effort design and the author says so up front. Known issues are listed, not hidden: no over-voltage clamp on the sense pin, "3.5-wire" rather than a true 4-wire return, an LM358 that is at the edge of what milliohm work wants, assumed rather than measured GPIO resistance.

That is the whole point of publishing it: one person with a bench and a multimeter can turn this from a design into a working instrument. If that is you, the most useful thing you can do is open a hardware report.
